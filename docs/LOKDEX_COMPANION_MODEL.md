# LOKdex vs. Companion Model

## Core rule

The **LOKdex** is the large collectible character/card universe. It is designed to scale to many generations, sets, variants, ultra-rares, event cards, generated characters, duplicate copies, provenance, and eventually secure player-to-player trading.

A **Companion** is a separate, curated presentation/behavior profile based on one LOKdex character. Only a small subset of LOKdex characters should ever become active Spend It All companions/advisors.

Owning a LOKdex character does **not** automatically grant an animated advisor. A character must have an explicit companion profile for the current game.

## Spend It All initial rule

- Gen 1 LOKdex begins as a larger roster than the companion list.
- Spend It All initially supports five companion profiles.
- Only one primary companion is equipped at a time.
- More companions can be promoted gradually as their pixel animations, dialogue, reactions, and unlock paths are properly designed.
- Generated LOKdex characters are collectible/card-only by default.
- A generated or existing LOKdex character becomes a companion only through a deliberate curated companion profile.

## Why the systems are separate

The LOKdex may eventually support hundreds or thousands of characters and variants. Rendering all of them as advisors would create excessive UI noise, dialogue maintenance, animation cost, and balance pressure.

Keeping companions separate allows each game to choose a small cast appropriate to its experience while the same LOKdex collection remains portable across the broader G-Six/LOK ecosystem.

Example:

- `lokdex:g1:017` = Wolf Pup character/card identity.
- `pet-wolf-pup` = Spend It All companion profile inspired by that character.
- A future card game can use `lokdex:g1:017` without importing Spend It All's risk warnings or HUD dialogue.
- Another G-Six game could create its own companion profile for the same character with different animations and behaviors.

## Card-ready LOKdex data

Each LOKdex character can carry:

- stable character ID
- dex number
- generation and set
- species
- rarity
- affinity and archetype
- acquisition routes
- discovery hints
- card stats
- tags
- optional companion-profile reference

Owned card instances can later carry:

- unique instance ID
- variant such as standard, foil, holo, negative, glitch, gold, or event
- serial number
- acquisition source
- source game
- generation seed for generated characters
- favorite state
- trade lock
- transfer count

Local saves are sufficient for collection experimentation. Real trading must wait for authenticated accounts and server-authoritative ownership so a card cannot simply be copied through localStorage edits.

## Companion behavior contract

A companion profile defines only presentation and assistance behavior:

- linked LOKdex character
- host game
- advisor role
- anchor location
- reaction hooks
- dialogue set
- animation set

Companions remain non-pay-to-win in Spend It All. Commentary, reminders, reactions, and quality-of-life callouts are allowed; hidden income multipliers, better odds, or challenge advantages are not.

## Future growth

Recommended progression:

1. Keep the initial Spend It All companion cast small and polished.
2. Expand the LOKdex roster much faster than the companion roster.
3. Add collectible discovery and variant systems.
4. Add local packs/event rewards without trading.
5. Add generations and deterministic generated variants.
6. Add server accounts and authoritative ownership.
7. Add secure trading/gifting.
8. Let a future standalone card game consume the same LOKdex assets and owned-card records.
9. Promote selected fan-favorite LOKdex characters into new companion profiles over time.

The special future character **Loc** should remain reserved until its visual identity, personality, and role are intentionally designed. It should not be procedurally generated by the generic LOKdex generator.
